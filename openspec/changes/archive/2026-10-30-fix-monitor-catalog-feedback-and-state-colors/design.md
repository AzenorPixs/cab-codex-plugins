# Conception

Après mutation catalogue réussie, le serveur renvoie son snapshot projeté actuel dans la même réponse. Le client vérifie ce snapshot avant application, invalide les générations de lecture précédentes et vide le buffer SSE ; la cadence choisie reste inchangée. Les réponses de refresh obsolètes, y compris les erreurs, ne remplacent plus la vue après une gestion réussie. Un reçu sans snapshot valide affiche que le rangement est enregistré mais l’affichage reste à actualiser ; aucun POST automatique.

Classes de lignes BLOCKED/DONE/STOPPED explicites, fonds pastel lisibles (bleu/vert/orange), sélection conservée par marqueur distinct. Les badges restent textuels, calcul des états inchangé. Tests navigateur privés à cadence manuelle, archive/delete/restore sans reload, refus protégé et lecture retardée ; styles calculés Chromium/Firefox, sélection et UNKNOWN. Les sources réelles et catalogue de production ne sont jamais rangés pendant la recette.
