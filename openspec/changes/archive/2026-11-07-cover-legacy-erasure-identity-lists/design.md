# Projection typée et recapture de processus

Les deux noms entrent dans le registre des listes d’identifiants. Seuls les
éléments chaîne exactement membres du scope sont retirés ; valeurs booléennes,
ordre et éléments des pairs restent inchangés. Le transfert cab-continuity-v1
conserve son contrôle de digest puis son réancrage existant.

recover-preparation est autorisé uniquement sur un reçu signé STOPPING sans
entries ni expectedPeers : aucune projection contrôleur n’a été engagée.
L’inventaire de liaisons original doit correspondre et tous les RUN visés
rester clos. Le helper vérifie NativePID/SID/permissions, remet en ligne les
services à la version runtime explicite, contrôle leurs PID et le broker,
puis recapture ces identités en gardant STOPPING. Il ne déclare ni APPLIED
contrôleur ni PURGED. Une phase après projection ou une liaison modifiée refuse.

Les helpers2.4.1 et2.4.2 supportent le runtime2.4.0 déclaré pour cette reprise
existante. Le CABU global demeure postérieur à la phase critique.
