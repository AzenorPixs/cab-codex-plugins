# Décisions

Deux commandes : run.inspect_historical (lecture) et run.close_historical.
La confirmation exige le digest de l'inspection, un receipt_id stable, une
référence d'autorisation développeur et une justification. Une transaction
verrouille le RUN et revérifie ses preuves et protections. Répéter exactement
la confirmation renvoie le reçu existant sans relire des fichiers amendables.
Un conflit de contenu pour le même reçu est refusé.

Exiger profil direct WORKING, archive datée unique, source active absente,
proposal/tasks/review non vides, tâches présentes et toutes cochées, rapport
local lisible. Aucun effet non terminal, bail détenu, période ouverte ou
maintenance. Aucun nouveau reçu d'exécution, acceptation ou mesure rétroactive.
Le reçu mémorise les limites historiques et les anciens reçus inchangés.

La fermeture concerne le cycle CAB ; les preuves documentaires de tests et
livraison sont historiques, pas une qualification courante reconstruite.
